# ADR 0033: Bind cached manifests to their worker source

- Status: Accepted
- Date: 2026-10-09
- Amends ADR 0031.

## Context

The generator publishes a worker before publishing its manifest, allowing
early AOT compilation to overlap factory probes. Atomic writes protect each
file separately. An interrupted settings switch can therefore leave manifest
A alongside worker B. A's configuration fingerprint still matches when the
user returns to A, but B may omit factories required by A. Restored caches can
also mix these generations. Existence and manifest validation alone cannot
detect that pair.

## Decision

Add `worker_source_digest` to the private version-9 manifest. Compute it from
the UTF-8 bytes of the exact worker source being published, using the existing
FNV-1a identity algorithm for disposable state. Before accepting a cached
manifest, compare the digest with the expected local worker's bytes. Missing
metadata, a missing worker, or a digest mismatch is a cache miss and requires
generation before actions. Rebased restored caches must match the local source;
the manifest's stale absolute worker path is never used.

## Consequences

This additive cache metadata does not change protocol v1 or BuilderOptions.
Older version-9 cache entries are regenerated; builder/configuration identity
and code-based AOT/kernel reuse remain unchanged. The files retain their
individual atomic publication and early compile overlap. The digest verifies
the pair at reuse time; it does not add serialization for competing builds.
Existing prewarm locks and unstable-workspace fallback remain applicable.

## Validation

The settings compile fixture saves manifest A, obtains a valid empty worker B
through prewarm, then restores only manifest A to reproduce the interrupted
publication state. Editing an input forces factory execution on return to A.
Both JIT and AOT recovery compare exit success and generated bytes with stock,
then check no-op reuse and restored inputs. Without the guard the JIT sequence
fails with `Unknown builder`; the previous outputs remain committed.

Unit tests cover older unbound manifests and changed worker source. Dart digest
vectors include empty, ASCII and UTF-8 text to validate the Rust/Dart identity.
