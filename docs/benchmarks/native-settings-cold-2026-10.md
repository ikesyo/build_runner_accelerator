# Native settings: launcher startup and cold builds

## Finding and change

The settings parser imported the public `build_config.dart` barrel to use
`normalizeBuilderKeyUsage`. That also brought YAML/configuration parsing into
the launcher, including invocations without configuration flags. Import the
official `src/key_normalization.dart` directly instead. No normalization,
configuration precedence, cache identity, or fallback semantics change.
The bounded build_config 1.3.x versions provide this implementation; the
existing stock differential parser tests continue to validate its behavior.

Kernel depfiles contain 22 Dart sources on main, 127 before this fix, and 24
afterwards. Linked kernel sizes are 8,884,248 / 10,313,928 / 8,907,808 bytes.
Four alternating source `--version` runs per PR variant have medians of
1.251 s before and 0.581 s after. This isolates compilation/startup without
pub executable snapshots; it is not a build benchmark. A compilation depfile
test rejects importing the public configuration barrel or YAML into the launcher.

## Launcher-inclusive comparison

Linux x64, two-CPU cgroup quota, 8 GiB memory limit; Dart 3.13.3, Rust 1.98.1,
release native binaries, build_runner 2.16.2, build_config 1.3.3, analyzer
14.5.0, json_serializable 6.14.1, one worker. The tracked
`json_serializable_10_app` fixture has ten models.

Main is `eee7be0`; the pre-fix PR is `bf43094`; the fixed variant adds only
the normalizer import change to its production code. Before/fixed use the same
native binary; main uses its own release binary. All lanes resolve the same
external package versions. Three samples per lane alternate
main/before/fixed, fixed/before/main, main/before/fixed. No successful sample
is excluded. Metrics are disabled, and no verification or other compilation
runs concurrently with the measurements.

Each cold starts in the same disposable fixture/cache paths with generated
sources, the entire fixture `.dart_tool`, accelerator cache and analyzer cache
removed. Offline pub resolution is performed outside timing, with the path
dependency pointing at the corresponding checkout. SDK/pub/OS page caches
remain warm. The timed invocation, including launcher startup and synchronous
worker AOT compilation, is:

```sh
BUILD_RUNNER_ACCELERATOR_BIN=<matching-release-binary> \
BUILD_RUNNER_ACCELERATOR_CACHE=<disposable-cache> \
ANALYZER_STATE_LOCATION_OVERRIDE=<disposable-analyzer-cache> \
BUILD_RUNNER_ACCELERATOR_WORKER_AOT=1 \
dart --suppress-analytics run build_runner_accelerator build \
  --mode=rust --jobs=1 --force-aot
```

No-op retains all caches and unchanged source bytes. One-file renames `value`
to `valueEdited` in the first model; broad renames it to `valueBroad` in all
models, starting from original inputs. Both edits change generated bytes.
Every timed invocation exits successfully and its ten generated source files
are compared against stock for that case. No-op reports no native work, and
all native cases retain a compiled AOT artifact without JIT fallback. Generated
cache parts are not included in this particular comparison.

For warm comparisons, run the unchanged build immediately after the same
variant's cold build, as above. Switching variants in one retained workspace
can change the manifest signature or package_config and invalidate the action
graph. Merely omitting cache deletion does not establish a no-op; check the
native `No work to do` result rather than treating such a rebuild as warm.

Median wall seconds:

| Case | Main | PR before fix | PR after fix |
| --- | ---: | ---: | ---: |
| Cold, including AOT | 35.870 | 37.144 | 36.211 |
| No-op | 0.215 | 0.265 | 0.216 |
| One-file | 0.366 | 0.416 | 0.366 |
| Broad | 0.366 | 0.465 | 0.416 |

Cold CPU medians are 44.820 / 46.251 / 45.157 seconds. Cold ranges are
35.290–37.521 / 36.364–38.590 / 35.426–37.729 seconds. The initial invalid harness
attempt had an unrebased path dependency, failed before the first native
build, and is not part of this complete run.

The fix removes a measurable launcher compilation cost. In this small sample,
cold improves by 0.934 s relative to the pre-fix PR, but remains 0.341 s above
main; broad also remains above main. These three-sample results do not establish
statistical significance or prove the absence of remaining regressions.
A large mixed-builder Flutter workspace has not been reproduced here. This
build_runner 2.16.2 comparison also cannot establish performance or dependency
compatibility for a workspace using 2.16.1 with locally relaxed constraints.
Re-measure that workspace with the fixed launcher and retain first-run costs
unless their cause is independently confirmed.

The existing `scripts/benchmark_cold_aot.py` can independently reproduce the
before/fixed cold comparison by supplying the pre-fix checkout as
`--baseline-root`, the fixed checkout as `--candidate-root`, and their shared
release binary as `--native`. Its warm edits append comments, unlike the
output-changing edits above; those warm numbers should not be conflated.

## Worker-source binding follow-up

The subsequent review fix binds cached manifests to their generated worker
source ([ADR 0033](../adr/0033-manifest-worker-source-binding.md)). It adds one
local worker read and FNV-1a digest calculation during cache acceptance. The
cold/incremental table above predates this fix and is not a measurement of it.

On the same machine and SDKs, compare release native binaries from `3b79e01`
and that commit plus the binding fix. Use the current source launcher for both,
with `--mode=rust --jobs=1 --force-aot`, retaining the settings fixture's default
configuration, workspace and cache. After one untimed no-op per binary, run
15 alternating pairs, reversing order in every other pair. No verification or
compilation runs concurrently. Every measured build reports `No work to do`,
exits successfully and retains bytes identical to stock's `.out`/`.marker`
outputs. The worker source is 511 bytes.

Launcher-inclusive no-op medians are 0.554 s before binding and 0.550 s after;
CPU medians are 0.950 / 0.940 s. This small fixture shows no measurable increase
above launcher noise; it does not establish the cost for large worker catalogs
or remeasure cold builds. Binding itself does not add YAML dependencies to the
launcher or change compile-artifact identity.
