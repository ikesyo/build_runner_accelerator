# Build telemetry overhead check (2026-11-06)

This checks native-command telemetry overhead, separately from stock/native
speedups. Linux x86_64, stable Rust 1.98.1, Dart 3.13.3, Release frontend,
resolved `fixtures/json_serializable_app`, two workers and warm AOT. A temporary
copy of the model with a distinct class/part name supplies two parallel inputs
and four actions. AOT preparation finishes before timing; no other checks run
alongside the timed commands.

The timing samples were collected during telemetry implementation on main
`5ae9ee8`, before the graph/hash changes in #164 and before the final builder-ID
and drop-summary metadata additions. They are not measurements of the rebased
implementation. Each command runs the native frontend, including its process
supervisor, without the public Dart launcher:

```bash
rust/target/release/build_runner_accelerator build \
  --root "$PWD/fixtures/json_serializable_app" \
  --dart /path/to/dart --force-aot --jobs 2
```

The enabled lane sets `BUILD_RUNNER_ACCELERATOR_OTEL_FILE` to a fresh file in a
temporary directory outside the fixture. Two order-reversed pairs per case:
off/on, on/off. Incremental edits change comments in both inputs, forcing
regeneration while preserving generated bytes. Samples in execution order,
milliseconds:

| Case | Off, On | On, Off |
| --- | --- | --- |
| No-op | 12.186, 12.043 | 12.281, 12.076 |
| Two-input incremental | 115.912, 161.256 | 118.626, 158.757 |

The incremental difference reverses sign. Two pairs on this tiny fixture do
not establish a stable overhead percentage or production performance claim.
The disabled path was inspected for absent SDK/context/exporter/worker-report
allocations; it was not compared with a separately compiled main binary.

Timed No-op captures contain 14 spans / 6,118 bytes; incremental captures contain
96 spans / 41,836–41,839 bytes. A final untimed two-worker capture with the
additional metadata contains 96 spans / 43,282 bytes. Generated file inventories
and bytes match with tracing off, on and an unavailable file destination. The
unavailable destination returns build success in 12.048 ms. An unreachable
`OTEL_EXPORTER_OTLP_ENDPOINT` does not cause network export; explicit post-build
curl to an unavailable local receiver fails independently. No live Collector
acceptance test was performed.

For activation, inspection and explicit OTLP forwarding, see
[development](../development.md#build-telemetry). For the design and bounds, see
[ADR 0048](../adr/0048-build-telemetry.md).
